## Problem Statement

Mohammed ships product and code slower because his Grok Bot team cannot assign different models (GPT / Claude / Grok / others) per bot. He is stuck on one stack. He also wants bots that can talk to each other and a Grok-Bot-easy UI, but the **measured daily pain** is model lock + tab-hop / quality compromise — not missing chrome.

North star: a DeepSeek Harness Electron desktop that feels like Grok Bot (personas, skills, routines, memory, easy UI, bot-to-bot). First ship must not wait for that full platform.

## Demand Evidence

- Pre-product: no external users yet. Customer = founder.
- Uses Grok Bot daily.
- Concrete limit this week: cannot assign different models per bot — stuck on one stack.
- Behavior: most working days he either hops to Cursor/Claude apps or accepts worse quality on one model.
- Not waitlist interest — repeated personal workflow friction.

## Status Quo

- Primary: Grok Bot for multi-bot team workflows.
- Workaround A: jump between Grok Bot and Cursor/Claude (or similar) by hand when another model is needed.
- Workaround C: run everything on one model and accept worse quality.
- Cost: daily hops or daily quality compromise; context and handoffs degrade across apps.
- Real competitor is Alt-Tab + settling — not an empty market.

## Target User & Narrowest Wedge

**Target user:** Mohammed Al-Madhoun — ships product/code with a multi-bot team; slowed when models cannot be mixed in one team.

**Narrowest wedge (first ship):** On DeepSeek Harness Electron desktop:
1. Multiple bots/agents, each with its **own model/provider** (at least GPT / Claude / Grok / DeepSeek as configured).
2. **Basic bot-to-bot messaging** (SendToAgent-style: one bot can message another; user can orchestrate).
3. UI good enough to replace the daily hop for that workflow — not full Grok Bot parity.

**Out of wedge (later phases toward north star):** rich personas/anti-jobs, skills library UX, routines/automations, durable memory productization, full connector surface, polished Grok-Bot-identical chrome, fleet healthchecks, etc.

## Constraints

- Build on fork of deepseek-ai/deepseek-harness (local: `DSH - MzM Bot`, origin `mohzmadhoun/dsh-mzm-bot`, upstream DeepSeek).
- Prefer Cordis plugin seams (agents, llm providers, subagent, Electron apps/desktop) — no one-off hacks that block later phases.
- Tooling: gstack + Spec Kit (constitution → per-phase specify→plan→tasks→implement); Linear as task tracker.
- Team: DH Lead / Spec / Architect / Electron / Runtime / Verifier + DH Product Owner Assistant.
- Must beat Alt-Tab on day-one value for Mohammed's workflow.

## Premises

1. Per-bot multi-model is the wedge; full Grok-like is the north star (A→C), not either/or.
2. Wedge must sit on real DSH seams (agent identity, model registry, subagent messaging, Electron shell) so C is extension not rewrite.
3. Landscape (Codeg, Agentre, ClawTab, OpenClaw multi-agent) already covers multi-engine cockpits — DSH fork wins if we need **plugin-native personas + Grok-Bot-style bots**, not another CLI aggregator.
4. Shipping C first without A is platform risk; shipping A as a throwaway outside plugins makes C hard.

## Approaches Considered

### Approach A: Wedge on DSH
Per-bot models + basic bot messaging on DSH Electron. No full Grok parity yet.

### Approach B: Orchestrator over CLIs
Codeg/Agentre-style multi-engine cockpit; skip deep DSH product clone.

### Approach C: Full Grok Bot clone on DSH first
Personas, skills, routines, memory, easy UI, bot-to-bot — long platform before daily pain is fixed.

### Approach D: Don't build
Keep Grok Bot + hop.

### Approach A→C (chosen): Wedge first, path to full clone
North star = C. First ship = A on durable seams.

## Recommended Approach

**A→C.** Design and implement the wedge on DeepSeek Harness agent/model/subagent/Electron primitives. Explicit roadmap phases after wedge (Spec Kit per phase): personas & anti-jobs, skills UX, routines, memory, connectors, UI polish to Grok-Bot-easy.

Rationale: matches demand evidence; keeps north star; avoids empty-market Alt-Tab competitor by shipping something that removes the hop for multi-model teams; avoids Codeg-class duplication by owning the harness plugin model.

## Success Criteria

**Wedge (phase 1) — measurable:**
- Mohammed can create ≥2 bots with **different** models and complete a real work session without opening Cursor/Claude for model reasons.
- One bot can send a message to another and the recipient acts (or user sees the handoff) without copy-paste.
- Time-to-first multi-model team session < 30 minutes on a clean machine (documented).
- DH Verifier can re-run an acceptance path on the real Electron app.

**North star (later):** Grok-Bot-comparable multi-bot product surface on DSH (personas, skills, routines, memory, easy UI) — defined per later Spec Kit phases, not this doc.
